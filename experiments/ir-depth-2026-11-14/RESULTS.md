# 深度复测：241 块 / 16 个 next 节点 / 缩进 29 层（2026-11-14）

> 叙述版结论。[RESULTS-DEPTH.md](RESULTS-DEPTH.md) 由 `score.mjs` 生成，[RESULTS-DEPTH.json](RESULTS-DEPTH.json) 是逐项原始分。
> 前两轮：浅层 35 块（[../ir-format-2026-11-14/RESULTS.md](../ir-format-2026-11-14/RESULTS.md)）、宽度 218 块（[../ir-large-2026-11-14/RESULTS.md](../ir-large-2026-11-14/RESULTS.md)）。下一轮全量 1494 块：见 [../ir-mlkem-2026-11-14/RESULTS.md](../ir-mlkem-2026-11-14/RESULTS.md)。

## 0. 为什么单独测深度

前两轮的规格里**一个 `next` 都没有**：任务全是「单个 RETURN 表达式树」。而 `next`（语句链）恰好是两种格式差异最大的地方——IR 的 `next` 直接挂下一块节点，Blockly JSON 的 `next` 必须再包一层 `{"block": …}`。这是唯一没测过的结构维度。

另一个现实约束：这份代码库里深度和规模强绑定。全仓最深的真实树是 `ML_KEM_Encaps`（深度 22），而那正好是 1494 块的整体；`size 90–160 且深度 ≥15` 的子树**一个都不存在**（树是 28 条 `variables_set` 的链，表达式侧最深只有 6）。所以深度任务只能从这条链上截段。

## 1. 任务

截取 `ML_KEM_Encaps` 的前 17 条语句（真实块树，只切断链尾），包成一个 `procedures_defreturn`：

| 指标 | 值 |
|---|---:|
| 块数 | 241（17 条语句 239 块 + RETURN 1 + 定义 1） |
| 语句链 | 17 块 / **16 个 `next`** |
| 规格最大缩进 | **29 层**（58 个空格） |
| 块类型 | 16 种 |
| 紧凑体积 | IR 14 900 字符 / JSON 20 480 字符 |

透明说明：包装壳是合成的（`NAME=MLKEM_SEG`、`extraState.params: []`），链尾被切断后语义不完整（后面的语句引用前面的变量）。任务是**序列化**，不是执行；块树本身是真实的。

## 3. 深度放大了体积差，而且比前两轮明显

| 指标 | IR | JSON | 差 |
|---|---:|---:|---|
| 紧凑字节 | 14 886 | 21 155 / 21 639 | **IR 小 30%–31%** |
| 每块紧凑字节 | 61.8 | 87.8 / 89.8 | — |
| 缩进后文件字节（各自缩进风格） | 57 200（1 空格/层） | 119 061（2 空格）/ 213 424（4 空格） | — |
| 缩进字节占比 | 69% | 79% / **88%** | — |
| 折算到 1 空格/层 | 57 200 | ≈ 72 100（B1）/ ≈ 72 600（B2） | **JSON 仍大 26%** |

两个可直接引用的结论：

1. **紧凑体积差随深度变大**：浅层 22%–23% → 深层 **30%–31%**。原因是 JSON 每个 `next` / 每个输入槽都多一层 `{"block": …}` 包装，深树里这些包装是逐层叠加的；
2. **缩进会把差距进一步放大**：四席都选择了缩进输出，缩进字节占到 69%–88%；其中一席用了 4 空格，文件涨到 **213 KB**（紧凑的约 10 倍）。对 LLM 来说这是真实的输出 token 成本——深度越大，缩进宽度这个"风格选择"就越盖过格式本身。

按真实 tokenizer 实测（`cl100k_base`，见 [../MEASURED-TOKENS.md](../MEASURED-TOKENS.md)），本任务 **IR 4 167 token vs JSON 6 163 token（少 32%）**，与「22%–23%（浅层）→ 30%–31%（深层）」的字符差一致，token 口径略大。

## 4. 一次规格事故：`(then)` 的缩进会诱导把链读成嵌套

我的规格方言把 `(then)` 行放在父级缩进、下一块放在 +1 缩进（和普通输入槽同层）。A2 与 B2 两席都**主动指出**了这个歧义：

> 「按缩进当嵌套会把 next 挂到语句内部的 VALUE 子块上，链长会退化为 1 且语义错；我按『(then) 续接上一条语句块』解析。」

四席最终都按 `(then)` 标记解对了，但这个方言仍然脆弱：一旦模型按缩进栈解析，链会长退化成 1、嵌套深度虚增到 30（本轮第一次打分就撞上过这类读数：A2 的产物还在写入时被打分器读到，一度显示链长 1 / 深度 30；等它写完再打分即恢复 17 / 14。**所以判分必须在产物 mtime 稳定之后**）。

**建议的方言修正**（下轮实验用，不追溯改本轮材料）：把链上后续块渲染成**同一缩进**、加 `then:` 前缀：

```
  STACK ->
    variables_set VAR={"id":"v_H"}
      VALUE -> sponge_squeeze …
    then: variables_set VAR={"id":"v_G"}
      VALUE -> sponge_squeeze …
```

这样「缩进 = 嵌套、`then:` = 链」两者不再冲突。

## 5. 三轮合起来的结论

| 轮次 | 块数 | 链深 | 最大缩进 | 两臂正确率 | 紧凑体积差 |
|---|---:|---:|---:|---|---:|
| 浅层 | 35 | 0 | 2 层 | 全部精确 | IR 小 21%–30% |
| 宽度 | 218 | 0 | 5 层 | 全部精确 | IR 小 22%–23% |
| 深度 | 241 | 16 | 29 层 | 全部精确 | **IR 小 30%–31%** |

三个维度都没有分出正确率胜负，**唯一随难度单调增长的指标是体积**。因此对 IR 的判断维持上一轮修正后的口径：**冻结保留、不追加投资**；它的价值是「同样的树更短」，而它的正确率优势至今没有被任何一轮实验证伪或证实。
