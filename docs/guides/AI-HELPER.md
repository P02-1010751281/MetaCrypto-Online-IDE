# AI 助手：文档检索、答案出处与自带 key 的模型选句

MetaCrypto Online IDE 的 AI 助手是一组本地优先的检索工具：仓库文档、标准 PDF 页文本与积木索引在构建期做成倒排索引，运行时在浏览器内检索，并给出「答案 + 出处」；不联网，也不需要模型。模型选句是可选增强：默认关闭，provider 与 key 由用户自填，模型只能在候选句里挑句子，不能改写句子、补充内容或替换出处。

本页说明三个入口的现有行为：侧栏的「问答助手」（查文档 / 查积木）、左栏第 5 个面板「从代码生成工作区」（「更多」菜单里也有同一项），以及第 6 个面板「标准 → 工作区」（预览 + 人签核）。检索与作答的评测读数不属于使用说明，见[可行性调研](../research/AI-HELPER-RESEARCH-2026-11-13.md)与 `experiments/ai-helper-2026-11-14/` 下的记录。

## 1. 入口与适用边界

| 入口 | 位置 | 作用 |
|---|---|---|
| 问答助手 | 左侧活动条上的助手图标；再点一次回到「文件」面板 | 「查文档」与「查积木」两个 tab 共用一个面板 |
| 从代码生成工作区 | 左侧活动条上第 5 个图标，是个面板（「更多」菜单里也有同一项） | 把粘贴或选中的代码反解析成积木工作区 |
| 标准 → 工作区 | 左侧活动条上第 6 个图标（预览 + 人签核） | 看标准切片的三档判据、缺口与原文锚点，逐条记录人签核，打开同一份切片的试点工程；不生成工作区 |

三条边界需要先说明：

1. **检索与答案不联网。** 文档索引、PDF 页索引与块索引都是构建期产物，随应用一起发布；查询在浏览器里完成，不发出任何请求。
2. **答案层是抽取式。** 答案逐句原样引用原文并带行号，界面标注「抽取自原文，逐句可回链（未接生成模型）」；不打开模型也能用。
3. **模型只做选句。** 打开开关后，问题与最多 5 个候选句（都来自同一个最佳段落）发给用户自己填的 provider；返回结果还要过引用完整性校验，越界即丢弃，检索答案与出处照常显示。

## 2. 查文档

### 2.1 输入与检索范围

在「查文档」输入一句话描述要找的内容（例如「分组密码的一轮包含哪几步」），输入停顿约 120 ms 后开始检索，结果最多 12 条。查询词会按术语表扩展（同义词、英文缩写与中文名），命中理由逐条列出命中的词。

查询行右侧的「含标准 PDF」是检索范围开关：

- 不勾选时只查 `docs/**/*.md` 的 Markdown 正文；
- 勾选后把标准 PDF 的页文本索引一起查，结果里会出现 `PDF` 标记与页码；
- PDF 原文是第三方标准稿，不随应用分发，所以 PDF 命中不打开文件，只给「路径 + 页码」。

PDF 索引缺失时（例如未跑 `npm run docs:index:pdf`），面板降级为只查 Markdown，并在状态栏说明原因，不静默少查一半。

### 2.2 结果列表与键盘

每条结果给出类型标记（`MD` / `PDF`）、文档标题、小节标题、`路径:行号`（PDF 为页码）与一段摘录；同一篇文档只保留最高分的段落，点一条就是落在那一行。

| 按键 | 行为 |
|---|---|
| `↑` / `↓` | 在结果间移动选中项 |
| `Enter` | 打开选中项 |
| `Esc` | 关闭面板 |

Markdown 命中会在新标签页打开文档中心并定位到该行；浏览器拦截新窗口时改为当前页跳转。PDF 命中把 `路径#page=页码` 复制到剪贴板并在右下角提示，用户自行在仓库里打开。

面板底部的「浏览全部文档」带当前查询词进入文档中心（`/docs?q=…`），用于在整棵文档树上继续找。

### 2.3 答案卡：答案与出处

有命中时，结果列表上方先给一张答案卡，标题为「答案」，标注「抽取自原文，逐句可回链（未接生成模型）」：

- 答案只从得分最高的那一段取句，句序保持原文顺序，不改写、不拼接；
- 每句前面有 `[n]` 序号，句子文本是原文摘录（已去 Markdown 标记）；
- 「出处 `路径:行号`」可点击，直接打开原文那一行；
- 「依据覆盖 N%」是问题词在选中句里出现的比例，用来判断这条答案覆盖了多少提问；
- PDF 命中的正文不可切句，只给页摘录，并明确标注「PDF 页摘录」。

### 2.4 答不出来时

语料里没有能直接支撑回答的段落时，答案卡不拿「最近的一段」冒充答案，而是：

1. 明说「没有找到能直接回答这句的依据」；
2. 列出缺的问题词（最多 6 个，`缺：…`）；
3. 提示下面列出的最近相关段落可以自己核对。

这条规则决定了下方的结果列表始终保留：答不出来不等于没有相关材料。

## 3. 查积木

「查积木」把自然语言描述映射到可拖入画布的块类型：

- 输入一句话描述要做的事，或只做结构化筛选；
- 「筛选」默认折叠，展开后可按输入类型 / 输出类型过滤（`Bytes`、`IntList`、`Bits`、`Number`、`String`、`Boolean`、`SBox`）；
- 每条结果给出块标签、块类型标识、输出类型与命中理由；
- 点击结果或按 `Enter` 把该块插入画布当前可视区（起点为可视区左上偏移 40 px，连续插入按 24 px 错开，避免叠在一起）；`↑` / `↓` 移动选中项，`Esc` 关闭面板。

每条结果右侧的「查文档」会把「这个块在文档里怎么说」反查过去；这类块多是共享数学原语，文档里本来没有单独页面，空结果也是答案。

## 4. 两个 tab 的联动

两个 tab 共用一个入口，互为对方的下一步：

| 方向 | 出现条件 | 行为 |
|---|---|---|
| 文档 → 积木 | 该文档的命中内容能派生出块词表里存在的标识符 | 结果行出现「查积木」，点击切到积木 tab 并带上派生词 |
| 积木 → 文档 | 总是出现 | 结果行出现「查文档」，点击切到文档 tab 并带上块相关查询词 |

联动只在下一次切到对面 tab 时生效；手点 tab 会清空上一次带入的查询词，回到干净输入。

## 5. 从代码生成工作区

左侧活动条上第 5 个图标「从代码生成工作区」（与「更多」菜单里的同一项）是 B 线的入口（参考实现代码 → 工作区），与「导入工作区」不是同一条路径：导入的是既有工作区文件，这里是从代码反解析出新工作区。它和另外四个一样是**互斥面板**：停靠在左栏里（宽 460px），画布仍然可见可操作；窄屏设备上栏折成顶部横条，它以浮层呈现。

操作顺序固定为「解析 → 核对诊断 → 载入」，每一步都可以停：

1. **输入**：粘贴代码，或用「选择文件」读取（上限 2 MB，超过即拒绝）；
2. **解析**：只产出工作区状态与诊断，不碰画布；
3. **核对**：诊断逐条标注「未识别」或「语义可能不同」，最多列 20 条，标题给出总数；
4. **载入**：「载入工作区」是显式动作，按钮旁写明会替换当前画布多少块、且无法撤销。

两条识别路径：

| 代码形态 | 路径 | 说明 |
|---|---|---|
| 本平台生成的 Python | 模板匹配 | 按生成器写出的形态逐语句还原 |
| 其它 Python | 标准库语法树（AST） | 只还原结构；形参类型落到默认值 `bytes`；翻不出来的节点单独警告 |

当前不支持 JavaScript 与 C/C++ 参考实现：判成 JavaScript 时直接说明「不会载入任何块」，不逐行列噪音；代码里识别到函数但两条路径都拼不出块时，明确拒绝生成半成品工作区，并列出识别到的函数名。

语法树解析器就是浏览器内的 Pyodide Python 运行时（约 12 MB），随应用同源打包（`public/pyodide/`），首次解析时加载、之后复用，不依赖外部 CDN；加载或解析失败会原样报出原因（例如资源缺失、解析超时 45 秒）。

## 6. 标准 → 工作区（预览 + 人签核）

左侧活动条上第 6 个图标是 A 线的入口（标准原文 → 工作区）。把「标准切片 → 条款单元 → 三档判据」摊开给人看，**不生成工作区**；判据旁记录**人签核**：谁、什么时候、对哪一条签的还是拒的、备注，以及当时的判据指纹。

| 视图 | 回答什么 |
|---|---|
| 标准切片 | 目前三份切片的裁决：NIST FIPS 180-4（SHA-2）、NIST SP 800-38B（CMAC）与 NIST SP 800-38C（CCM） |
| 条款单元 | 条目页拆出的条款，带标准定位与步骤数 |
| 三档判据 | 能搭 / 部分 / 不能——条款的步骤能不能用现有画布块搭出来 |
| 缺口与口径边界 | 哪些步骤只在生成器闭包里、哪些参数范围块模型不表达 |
| 原文锚点 | 每条锚点带行区间，点开在文档中心定位到那一行 |
| 试点工程 | 同一份切片用现有块搭出来的多文件工程（SHA-2 33 块 / CMAC 41 块 / CCM 113 块），带官方向量驱动 |

三件限定必须与判据同时读：

1. 判据是**构建期机器候选**：`scripts/p4-*` 产出裁决 JSON，`scripts/build-verdicts-index.mjs` 汇总成 `src/services/ai-helper/verdicts-index.json`（构建前自动重跑）；
2. **语义等价一律未验证**（`semantic_equivalence = unverified`）：档位只回答「能不能搭」，不回答「实现是否符合标准」；
3. **签核在人**：面板顶部给出「已签核 / 拒签 / 待签核」计数，条款里可记录签核人、备注并签核或拒签。签核绑定当时的判据指纹（步骤文本、缺口、锚点行区间等），产物重生成后条款一变，旧签核显示为**数据已变，需复核**，不会继续算「已签核」。记录只存浏览器本地，可导出 JSON（自带导出时与记录时两枚索引指纹），不提供一键生成。

判据旁边还给出**试点工程**：同一份切片真用现有块搭出来的多文件 project，积木总数与文件清单都来自制品。点「打开试点工程」只是在本机项目列表里**复制一份可编辑记录**并跳到编辑器——它不改动构建制品，也不是「按原文生成工作区」；本机已有同一份时先问是覆盖还是打开现有（覆盖会丢掉那份里的改动）。试点工程本身仍是机器候选演示，不是标准符合性证明。

改了裁决 JSON 或试点工程要重跑 `npm run verdicts:index`（`verdicts:index:check` 只比对不写）：索引与 `src/services/ai-helper/pilot-projects/*.json` 一起重生成，过期时会指名是哪一份。源 JSON 必须已入库，否则脚本拒绝生成——制品要能被别人复现。

## 7. 让模型选句（自带 key）

### 7.1 默认关

「让模型选句」默认关闭。不勾选时应用不发出任何外部请求，也不需要填 key；开关打开但还没有配置时，状态位显示「未配置模型」，勾选动作会直接打开设置窗。

### 7.2 配置

设置窗「模型设置（自带 key）」有三个必填项、一组可选单价与一条风险提示：

| 字段 | 校验 |
|---|---|
| Base URL | 必须是 `https://` 任意主机，或本机 `http://127.0.0.1` / `localhost`；其它主机的明文 http 直接判无效 |
| 模型 id | 必填 |
| API key | 必填，只进请求头 |

单价是可选项，用来把本次调用的 token 换算成金额：按**每百万 token** 填，输入与输出分开（两者价差常常是 3–5 倍）；输出单价留空表示与输入同价，币种留空按 `USD`。仓库里没有价目表——不同 provider、模型与时间价格都不同，内置一张表只会过期，所以价由你按自己的账单填。留空就不显示费用：没填单价不等于免费。

仓库不内置任何默认 provider、默认模型或 key；空配置就是「没接模型」，不是「用默认的」。

### 7.3 key 存在哪里

| 档位 | 何时写入 | 生命周期 |
|---|---|---|
| 会话档（默认） | 直接「保存」 | 关掉标签页即失 |
| 持久档 | 勾选「记住」再保存 | 写入 `localStorage`，关浏览器后保留 |

两份互斥：写入持久档会清掉会话副本。「清除」把两个档位一起清空，并关闭开关、清空状态位。

### 7.4 一次调用做了什么

| 项 | 取值 |
|---|---|
| 协议 | OpenAI 兼容 `chat/completions`（拼在 Base URL 后面） |
| 发送内容 | 用户问题 + 最多 5 个候选句（含每句 id、出处行），候选只来自最佳段落 |
| 采样 | `temperature: 0`、`stream: false`，输出上限默认 300 tokens（可调） |
| 超时 | 默认 20 s，到点真取消 |
| 重试 | 0 次；失败不自动重发 |

key 只放在 `Authorization` 头里，不进请求体、不进错误信息。

### 7.5 结果如何被校验与采用

模型可以「选句」，也可以写一两句解释；两者过不同的关，因为它们的证据地位不同。

**答案句**只能引用候选 id，并按「最多 5 句」返回。返回值要过引用完整性校验，三类越界各自说明原因，而不是笼统报「失败」：

| 越界 | 界面说法 |
|---|---|
| 引用了候选之外的 id | 模型选了候选之外的句子（id 不在本次候选里） |
| 同一句选了多次 | 模型把同一句选了多次 |
| 超过上限 | 模型选的句子超过上限 |

**解释**（`notes`）不是证据：它在答案卡上分区显示（左侧竖线 + 「模型说明（不进答案证据）」标签），并且**逐句要依据**——每句都必须点名它依据哪几个候选 id。挂不上候选 id 的句子**整句丢弃**，但不判整次失败：空文本、没标依据、依据里有候选之外的 id、重复、超过 4 句，五种情况都只丢那一句，界面上用一个 `−n` 计数显示被丢弃的句数（悬浮给出原因）。解释不会因为写得好变成证据，也不会因为没依据把可用的选句一起作废。

校验通过后，答案卡只展示被选中的句子，出处仍是那一段的 `路径:行号`——选句不会让出处指错文件。状态位同时给出本次调用读数：`模型选了 n 句 · N tokens · M ms`；填过单价时再追加 `≈USD 0.00054`（悬浮给出「按你填的单价估算，实际以 provider 账单为准」）。校验失败或模型拒答时，读数与费用照给，只多一行原因——失败的调用一样花了钱。

### 7.6 失败怎么显示

失败时状态位以「模型调用失败：」开头，逐类给出原因：超时（20 s）、鉴权失败（401）、无权限（403）、额度或频率受限（429，本次不重试）、模型没有按要求返回 JSON、返回空内容、网络错误、配置不完整，以及未知 HTTP 状态。

失败不吞答案：检索结果与出处照常显示，只是多一行原因。要再试一次，重新提问即可（不自动重试是刻意设计）。

### 7.7 风险与没做的事

- key 存在浏览器存储里，同源脚本与扩展可读，也可能进入磁盘备份；默认只存本标签页，关掉即失。
- 打开开关后，问题与候选句文本会发到用户自己填的 provider；是否可控取决于该 provider。
- **费用是估算，不是账单**：金额按你填的单价与 provider 返回的 `usage` 换算后四舍五入显示；缓存命中价、推理 token 的额外计费、阶梯价都不在模型内。provider 不返回 `usage`（或只返回合计、没有输入/输出拆分）时不估价——界面只说「未返回用量」，不拿 0 元顶上。
- 单价存在本机 `localStorage`（它不是密钥），「清除」只清密钥与配置，不会删掉已填的价。
- 真实 provider 未在仓库内验证（仓库不带 key）；现有验收使用本地假 provider 走真实 HTTP，穿 CSP。

## 8. 索引与语料维护

| 命令 | 作用 |
|---|---|
| `npm run docs:index` | 重建 Markdown 文档索引（`docs/**/*.md`，跳过点开头目录） |
| `npm run docs:index:pdf` | 重建标准 PDF 页索引 |
| `npm run docs:index:check` | 校验索引与当前语料一致 |

索引是构建期产物，与仓库文档同版本；新增或修改文档后必须重建索引，否则检索与答案仍按旧语料工作（`docs:index:check` 会报不一致）。检索本身不访问网络与后端，但两份大索引不是首屏包的一部分：Markdown 索引（约 4 MB）与 PDF 页索引（约 3.4 MB）在首次检索该范围时按需加载，块索引（约 288 KB）随面板一起打包。
